# Discordモデレーション検知Bot 仕様書

## 1. 目的

複数の小規模Discordサーバーで、冷笑、差別、性的表現、サーバー指定要注意語、薬物関連に該当する可能性が高いテキスト・VC発言を検知し、処罰ではなく表現の見直しを促す。

判定と音声認識はGroq Free Planを主系とする。テキストは`openai/gpt-oss-120b`、同モデルが429の間は`openai/gpt-oss-20b`、VC文脈判定は`openai/gpt-oss-safeguard-20b`、VC音声は`whisper-large-v3`を使用する。既知の強表現とAPI障害時はローカルJSONルールを安全網とし、音声API障害時は端末内の日本語Voskへ退避する。

## 2. 対象範囲

### テキスト監視

- `MONITOR_ALL_GUILDS=true`の場合はBot参加中の全サーバー。無効時は`DISCORD_GUILD_IDS`で指定したサーバー
- Bot起動後の新規メッセージと受信した編集イベント
- Botが閲覧できる通常テキストチャンネルとスレッド
- 日本語を含む多言語の外部LLM文脈判定とローカル安全網
- 同じチャンネルの直前3メッセージを最大180秒だけメモリ内で参照

DM、過去ログの一括走査、画像、動画、添付、リンク先、Bot・Webhook投稿は対象外とする。

### VC監視（任意）

- `VOICE_ENABLED=true`かつ`VOICE_AUTO_JOIN=true`の場合、各対象サーバーで人がいるVCへ自動参加
- 監視中VCが空なら、利用者がいる別VCへ移動し、候補がなければ退出
- 手動指定時は`VOICE_CHANNEL_IDS`のVCへ参加
- 1サーバーにつき同時に1VC、複数サーバーでは各1VCへ同時参加可能
- Discord音声を16kHz mono WAVへ変換し、最大10秒または発話終了単位でGroq Whisper Large V3へ送信
- RMS 80未満の無音・低音量区間と180ms未満の極短区間を端末側で破棄
- Discordの発話終了イベントが届かない場合も、発話後の無音フレームで残余音声を即時送信
- Whisper Large V3へ日本語を明示するが、監視語そのものは認識ヒントへ含めない。`avg_logprob >= -0.8`かつ`no_speech_prob <= 0.6`の区間を採用する
- Whisperの`verbose_json`品質情報から低信頼度・無音推定区間を除外
- ローカル強ルールに該当する文字起こしは、語彙ヒントなしの別Whisperモデルでも再認識し、文字列と内部ルールが一致した場合だけ通知候補にする。不一致・再照合失敗時は誤帰属防止を優先して破棄する
- VCの文字起こしはローカル語彙に該当しない文章も外部文脈判定の候補にする。ただし無料枠保護の間隔・日次上限を超えた分はローカル判定だけを行う
- テキストと同じ外部LLM文脈判定とローカル安全網

Botが参加していないVCの音声はDiscordから受信できないため検知できない。同一サーバーで複数VCが同時利用中の場合は現在監視中のVCを優先し、そのVCが空になった時点で利用者数が最も多いVCへ移る。

音声・文字起こしはBot側へ保存せず、認識区間の判定後に破棄する。過去音声、録音、音声再生は対象外とする。検知時は発言者のサーバー表示名を通知へ記載する。音声と文字列が外部サービスへ送信され、検知時に表示名が通知されることを、サーバールール等で参加者へ事前周知する。

## 3. 検知分類

### 差別表現

人種、民族、国籍、宗教、性別、性自認、性的指向、障害、疾病、年齢に加え、社会的に脆弱な集団への次の表現を対象とする。

- 明示的な蔑称
- 集団の一括り・本質化
- 劣等視、有害な固定観念
- 排除、権利否定、隔離
- 非人間化
- 障害・疾病の存在否定や「甘え」扱い
- 性的指向・性自認の病理化
- 「女々しい」「男らしくない」「男のくせに泣くな」等の性別に基づく侮蔑・役割強制

外部LLMは明示表現だけでなく、返信元を含む文脈、婉曲表現、隠語、集団責任、暗黙の排除、語順、省略された主語を考慮する。既知の明示表現はローカルルールでも補完する。属性名単独や中立的言及は成立させない。発言スタイルから性別らしさを推測せず、明示的な性別侮蔑だけを対象とする。性別侮蔑は相手を辱める作用もあるため、差別と冷笑の複合分類とする。

### 冷笑

特定相手への侮辱、見下し、嘲笑、突き放し、わざとらしい驚きや上から目線を対象とする。「草」「笑」「w」や一般的な冗談だけでは成立させない。

一般的な冷笑は、現在投稿または会話文脈で識別可能な対象があり、現在投稿に明確な見下し・嘲笑・侮辱がある場合だけ成立させる。外部LLMは冷笑のみ初期値80以上の信頼度を要求する。通常の反対意見、訂正、驚き、自己状況への愚痴、短い返事、友好的な軽口、対象のない笑いは検知しない。

サーバー固有の強い冷笑反応として「うお」「うおw」「どわー」「クイヤ」と表記揺れ、投稿末尾の「めう」を直接検知する。「クイヤ」は投稿内に出現した時点で成立する。「めう」は末尾だけを対象とし、中立的な語の説明、「うお座」「ドワーフ」は検知しない。

### 性的表現

下ネタ、露骨な性的行為・身体部位・性的興奮・ポルノ・性的な冗談や婉曲表現を対象とする。医療、教育、安全、同意、報道の中立的文脈は外部LLMで除外する。ローカル安全網では明示語を直接検知するが、「エッチング加工」「処女航海」「ちんちん電車」の既知同音異義語は除外する。

### サーバー指定要注意語

独立した英字語`ADHD`を大文字小文字・全角半角を正規化して検知し、「要注意語（ADHD）」として通知する。中立的な説明、自己申告を含め出現時点で成立するが、差別とは断定しない。`ADHDers`のように英数字語の一部となる場合はローカルルールで成立させない。直前文脈だけにADHDがあり、現在投稿にない場合も成立させない。

### 薬物関連

違法・娯楽目的の薬物名、薬物乱用・オーバードーズ、製造・栽培、所持、売買、譲渡、勧誘、摂取量・方法、隠匿、隠語を対象とする。一般的な処方薬、正規の治療、「ドラッグストア」「OD缶」など薬物行為を示さない語だけでは成立させない。サーバー方針として、明示的な違法・娯楽目的薬物名は中立的な報道、教育、防止、治療の文脈でも確認対象とする。

## 4. 判定処理

1. 現在メッセージをローカルルールで一次判定する。明白な成立時は即時通知し、部分ルールに一致する曖昧な発言または返信文脈がある発言だけを外部判定候補とする。
2. 外部判定候補では、現在メッセージ、利用可能な返信元、同じチャンネルの直前3件をGroqへ送信する。直前文脈は最大180秒、1件500文字、投稿者のID・名前を付けずメモリ内だけに置く。
3. 外部LLMはプロンプト内の本文を命令でなく未信頼データとして扱い、現在メッセージだけを差別・冷笑・性的表現・要注意語・薬物関連へ独立分類する。過去文脈単独の判定を現在投稿へ引き継がない。
4. Strict Structured Outputsで分類ごとの`detected`、信頼度0〜100、原文を引用せず、対象の種類と問題行為（能力への見下し、失敗の嘲笑、集団の排除など）を具体化した日本語1文の問題点要約を受け取る。
5. `detected=true`かつ信頼度50以上を既定の成立条件とする。
6. 外部判定は全体4秒間隔、VC由来5秒間隔、プロセス内の24時間窓でテキスト70件・VC300件までとする。VCは専用Safeguardモデルへ分離し、通常テキスト判定のモデル別無料枠を奪わない。429時は`Retry-After`、取得不能時は60秒の休止時間を置く。
7. API失敗・上限到達時は、通常閾値80からローカル退避閾値65へ切り替える。属性語や笑いだけでは成立させず、「対象＋直接侮辱」「属性＋排除・固定観念」「失敗＋嘲笑」など複数条件を継続検知する。VC音声APIが失敗・混雑・品質除外になった場合は、利用可能なら端末内Voskで同じ一時WAVを認識する。Vosk結果が6文字以上で、差別または冷笑の異なる内部ルールが2つ以上成立する場合に限り、外部再照合不能時もローカル通知を許可する。短い指定語・単独ルールは誤帰属防止のため外部再照合なしでは通知しない。

判定結果オブジェクトは検知有無、分類、点数、内部判定元ID、問題点要約だけを保持し、原文を保持しない。通知を組み立てる瞬間だけDiscordメッセージ本文またはVC文字起こしを参照し、改行を空白へ変換し、メンション・Markdown記号を無効化した最大240文字の該当発言を表示する。外部要約は改行除去、メンション文字の無効化、160文字上限を適用する。API障害時は分類別の定型要約を使用する。

## 5. 通知と重複抑制

テキストでは元メッセージへ次の形式で返信する。

> ⚠️ モデレーション対象表現の可能性を検知しました（種別：差別表現）<br>
> 発言者：サーバー表示名<br>
> 該当発言：「実際に検知された発言（最大240文字）」<br>
> 問題だった点：<br>
> ・差別表現：属性や立場を理由に相手を排除・劣等視する内容です。<br>
> 互いを尊重した表現に言い換えてください。

サーバー別の`ALERT_CHANNEL_IDS`がある場合は、分類、発言者のサーバー表示名、該当発言、問題点要約、元メッセージリンクを専用チャンネルへ送る。投稿者をメンションせず、点数と内部ルールIDは通知しない。

同じメッセージID・分類は1回だけ通知する。編集で新しい分類が成立したときだけ追加通知する。送信失敗時は重複状態を戻して再試行可能にする。

VCではサーバー別の専用テキストチャンネルへ次の形式で送る。

> ⚠️ VCでモデレーション対象表現の可能性を検知しました（種別：冷笑）<br>
> 発言者：サーバー表示名<br>
> 該当発言：「音声認識された発言（最大240文字）」<br>
> 問題だった点：<br>
> ・冷笑：相手の能力や言動を低く扱い、笑いものにしています。<br>
> 互いを尊重した発言を心がけてください。

発言者のサーバー表示名と文字起こしの該当箇所（最大240文字）を含めるが、話者メンションと元音声は含めない。メンバーキャッシュから表示名を取得できない場合だけユーザーIDを表示する。同一サーバー・話者・分類は20秒のクールダウンを設ける。この状態もメモリ内だけに保持する。

専用通知先が未設定の場合、対象サーバー内でBotが閲覧・送信できるシステムチャンネル、または最初のテキストチャンネルを自動選択する。

`/alert_channel`でサーバー管理者が同一サーバー内の送信可能な通常テキストチャンネルを指定した場合、そのIDを環境設定より優先し、テキスト・VC両方の通知先として再起動後も使用する。永続化するのはサーバーIDとチャンネルIDだけで、投稿本文、音声、文字起こし、表示名は保存しない。`/alert_channel_reset`でコマンド指定を削除し、環境設定または自動選択へ戻す。

## 6. 設定

| 環境変数 | 必須 | 内容 |
| --- | --- | --- |
| `DISCORD_BOT_TOKEN` | 必須 | Botトークン。保存・ログ出力しない |
| `MONITOR_ALL_GUILDS` | 任意 | `true`でBot参加中の全サーバーを対象。現在の自動起動では有効 |
| `DISCORD_GUILD_IDS` | 条件付き | 全サーバーモード無効時の対象サーバーID |
| `MONITORED_CHANNEL_IDS` | 任意 | 対象テキストチャンネルID。未指定は閲覧可能な全対象 |
| `ALERT_CHANNEL_IDS` | 任意 | `guild_id:channel_id`のカンマ区切り |
| `MODERATION_BACKEND` | 必須 | 常駐版は`groq` |
| `GROQ_API_KEY` | Groq時必須 | 環境変数またはmacOSキーチェーンからのみ取得 |
| `GROQ_TEXT_MODEL` | 任意 | 初期値`openai/gpt-oss-120b` |
| `GROQ_FALLBACK_TEXT_MODEL` | 任意 | 120Bが429の間に使う予備モデル。初期値`openai/gpt-oss-20b` |
| `GROQ_VOICE_TEXT_MODEL` | 任意 | VC専用安全判定。初期値`openai/gpt-oss-safeguard-20b` |
| `GROQ_SPEECH_MODEL` | 任意 | 初期値`whisper-large-v3` |
| `GROQ_CONFIDENCE_THRESHOLD` | 任意 | 初期値50、0〜100 |
| `GROQ_CYNICISM_CONFIDENCE_THRESHOLD` | 任意 | 冷笑だけの通知信頼度。初期値80、0〜100 |
| `GROQ_TIMEOUT_SECONDS` | 任意 | 初期値20秒 |
| `GROQ_VOICE_ANALYSIS_INTERVAL_SECONDS` | 任意 | VC外部判定の最短間隔。初期値5秒 |
| `GROQ_VOICE_DAILY_REQUEST_LIMIT` | 任意 | 24時間窓のVC外部判定上限。初期値300件 |
| `CONTEXT_MESSAGE_COUNT` | 任意 | 直前文脈の件数。初期値3、1〜5 |
| `CONTEXT_TTL_SECONDS` | 任意 | 直前文脈のメモリ保持秒数。初期値180、30〜600 |
| `VOICE_ENABLED` | 任意 | `true`でVC監視を有効化。初期値`false` |
| `VOICE_AUTO_JOIN` | 任意 | `true`で利用中VCへ自動参加・移動 |
| `VOICE_CHANNEL_IDS` | 条件付き | 自動参加無効時の`guild_id:voice_channel_id` |
| `VOICE_ALERT_CHANNEL_IDS` | 任意 | `guild_id:text_channel_id`。未指定は自動選択 |
| `VOICE_CHUNK_SECONDS` | 任意 | 外部音声認識へ送る最大区間。初期値10秒 |
| `VOICE_MIN_RMS` | 任意 | 無音・低音量除外のRMS閾値。初期値80 |
| `VOICE_MIN_UTTERANCE_MS` | 任意 | 送信する最短発話長。初期値180ms |

全サーバーモード無効時、サーバー別チャンネル設定は`DISCORD_GUILD_IDS`内だけを参照できる。旧`DISCORD_GUILD_ID`と`ALERT_CHANNEL_ID`は1サーバー時だけ互換対応する。

## 7. スラッシュコマンド

- `/vc_join`: 実行者がいるVCへ参加して監視開始
- `/vc_leave`: VCから退出してそのサーバーの自動参加を一時停止
- `/vc_auto`: そのサーバーの自動参加を有効・一時停止。停止時は現在のVCから退出し、有効化時は利用者のいるVCへ即時同期する
- `/vc_status`: 現在のVC、自動参加、音声受信、認識・除外件数、最終認識、直近エラー
- `/bot_status`: 稼働時間、判定・通知件数、会話文脈、API、Discord再接続、VC接続状態
- `/permissions`: 現在のチャンネルでのBot実効権限
- `/alert_channel`: テキスト・VCの検知通知先を設定し、チャンネルIDだけを永続化
- `/alert_channel_reset`: コマンド指定を解除して環境設定または自動選択へ戻す
- `/alert_channel_status`: 現在適用されている通知先を表示
- `/ping`: Gateway応答速度
- `/moderation_help`: コマンド一覧

Developer PortalのBot説明にも11コマンドの短縮一覧を掲載する。

参加・退出・自動参加変更、通知先の設定・解除・確認は`Manage Guild`権限を実行時にも検証する。通知先設定時は同一サーバー所属とBotの`View Channel`・`Send Messages`実効権限を検査する。応答は原則ephemeralとし、操作した本人だけに表示する。一時停止状態はメモリ内で、再起動時に既定の自動参加へ戻る。

## 8. Discord・音声依存要件

- Python 3.9以上、`discord.py==2.7.1`
- Message Content IntentをDeveloper Portalで有効化
- `View Channel`、`Read Message History`、`Send Messages`、必要時`Send Messages in Threads`
- VC時のみ`Connect`とGuild Voice States intent
- スラッシュコマンド用`applications.commands`スコープ
- 管理者、Manage Messages、Speakは不要
- テキスト判定はGroq Chat CompletionsのStrict Structured Outputsを使用
- VC認識はGroq Speech-to-Textの`whisper-large-v3`を使用
- PCM復号用のネイティブ`libopus`を起動時に検証・読込する。このMacではHomebrewの`opus`を使用
- 音声受信は`discord-ext-voice-recv`の受信前DAVE復号・復号待ちパケット破棄対応コミット`bec0481`へ固定

Discordは2026年3月1日以降の通話でDAVE E2EEを必須としている。音声受信拡張のDAVE対応は未マージPR由来であり、VC機能は実験的と位置付ける。VC初期化・接続に失敗してもテキスト監視は継続する。

## 9. ログとプライバシー

- 本文、検知語、VC音声、文字起こし、トークンをBotのログ・DB・ファイルへ保存しない。
- コマンドで選択した通知先は`config/runtime_alert_channels.json`へサーバーIDとチャンネルIDだけを保存し、ファイル権限を所有者限定にする。この実運用ファイルはGit管理しない。
- 直前文脈はチャンネル別に最大3件・180秒だけメモリへ置き、期限切れ、編集置換、Bot終了時に破棄する。投稿者情報は保持しない。
- 本文、返信元、直前文脈、VC音声チャンクはGroqへ送信する。通常推論は既定で保持されないが、障害・不正利用調査時の一時保持可能性は利用者へ明示する。
- 運用ログは起動、再接続、ID、分類、例外型など内容を伏せた情報だけとする。
- 音声はメモリ上で48kHz stereo PCMから16kHz mono WAVへ変換し、Groqへ送信後に破棄する。
- 投稿削除、警告回数管理、ミュート、BAN、自動処罰は行わない。

## 10. 障害時の動作

- 必須設定が不正なら、秘密を表示せず起動を中止する。
- Discord切断時はクライアントの再接続を利用する。
- 対象外イベントは黙って無視する。
- メッセージ取得・通知・VC接続・音声認識の失敗は内容を伏せて記録し、可能な他機能を継続する。
- VC監視停止を管理用通知先へ知らせる。同一サーバーの連続エラー通知は5分間抑制する。
- Groqの429、5xx、タイムアウト時は秘密や本文を記録せず、テキスト判定はローカル退避閾値、音声認識は利用可能な端末内Voskへ退避する。429は待機時間中の再送を行わず、音声チャンクは処理後に破棄する。
- 再起動で重複通知状態は失われるが、過去ログを走査しない。

## 11. 受入条件

- 全サーバーモードではBot参加中の全サーバー投稿を処理し、DMを無視する。
- 正規化、難読化、強い差別表現、属性と敵対表現の組み合わせ、複雑な語順、冷笑、複合分類、編集、重複抑制を自動テストする。
- 「草」だけ、中立的属性言及、批判的引用、一般的冗談、「ドワーフ」を通知しない。
- 「うお」「うおw」「どわー」と代表的な差別表現を通知する。
- 「クイヤ」、投稿末尾の「めう」、「女々しい」等の性別侮蔑を通知し、「めう」の中立的説明は通知しない。
- 下ネタ・性的表現を独立分類で通知し、既知の同音異義語を通知しない。
- ADHDの単独・自己言及を要注意語として通知するが差別と表示せず、英数字語の一部は通知しない。
- 違法薬物名、乱用、売買、勧誘、摂取方法、薬物隠語を薬物関連として通知し、通常の処方・治療や同音異義語だけでは通知しない。
- Bot、Webhook、DM、対象外チャンネルを無視する。
- 公開通知に発言者の表示名、該当発言（最大240文字）、問題点要約を含め、話者メンションを発生させない。
- PCM/WAV変換、短発話flush、外部文字起こし結果、Vosk退避、API割当制御、VCクールダウンをテストする。
- 無音・極短発話、Whisper低信頼度・無音推定区間の除外、VC参加案内、障害通知抑制をテストする。
- 発話終了イベントがなくても後続無音で短い発話を送信し、低音量の明瞭音声と珍しい短語を過剰除外しないことをテストする。
- 人工例文データセットで適合率・再現率・F1・完全一致率を再現可能に計測し、本文を評価出力へ載せない。
- VC自動選択、空室退出、コマンド登録、管理権限、通知先自動選択をテストする。
- 通知先コマンドの権限、同一サーバー検査、Bot送信権限、テキスト・VC共通上書き、解除、再起動後のID復元をテストする。
- 全自動テストと構文検査が成功する。
- 実VC確認は参加者同意のあるテストVCで別途実施する。

## 12. 既知の制約

生成AIとWhisperを用いても、世界中の差別・冷笑を100%列挙・理解・検知することはできない。文化依存の隠語、当事者による語の再利用、雑音、重なり発話、極端に短い発話には誤検知・見逃しが残る。無料枠はモデル別のリクエスト、トークン、音声時間制限を受け、上限は提供者により変更され得る。一次選別対象外または日次割当超過中の曖昧表現はローカル結果だけになる。通知は処罰の唯一の根拠にしない。
